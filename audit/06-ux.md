# Phase 06 — UX (flows, placement, states)

Date: 2026-09-26. Starting at `phase-05-done` (`d70117a`). Scope: structure, flows, placement, states, copy. Visual styling is phase 07.

## Phase A — Understand

Screenshots of every route and key state at 375 / 768 / 1440 px, signed out and signed in, with `apps/web/e2e/screenshots.mjs` against the dev stack (seeded demo catalog): 64 files in `ux-screenshots/before/` (kept out of git; see "Screenshots" below). The UI is English-only (no locale switch, no i18n system) and dark-only, so there is no RTL or light-mode pass; mixed Arabic/English store titles were handled in phase 05 (FE-09).

Flows walked: land → search → results → filter/sort → product → compare stores → go to store; sign up / sign in / sign out; watchlist; alerts; notifications; pricing; seller.

## Phase B — Audit

Checked and fine (no change):
- Search is reachable from every page (navbar on desktop, menu + home hero on phones; the search page has its own box).
- Empty query browses the catalog; a no-result search says so and polls while a live fetch runs; the query survives reload (phase 05).
- Prices: every offer shows its own currency; the product price box is in the base currency (EGP).

## Summary

- The product page now answers "which store is cheapest, and take me there" in its first price box, and lists every store's offer directly under the header, cheapest buyable first, with a full-width "Go to <store>" on phones instead of a column scrolled off-screen.
- Owner decision D-6 is delivered: color chips filter a product's offers, and Best Deal follows the chosen color.
- Duplicated price figures and filler tiles are gone; the price history is one section.
- Search: one Sort control on the results bar (no more "Lowest price · Descending"); compact result rows on phones (about 30% shorter page) with three-line titles that keep storage/RAM/color visible; the unusable Category ID field is gone.
- Cards no longer nest a button in a link; the watchlist heart is visible on touch screens; product links show a pending bar.
- Placeholder "collections" content is no longer promoted anywhere.
- The phone menu reaches every section the desktop bar does; signing in returns you to where you were; a rate-limited login explains itself in plain words.

## Remaining items

- D-23 (collections), D-24 (category filter), D-25 (match confidence), D-21 (store-link click tracking) need the owner.
- The filter panel on phones still opens inline above the results rather than as a bottom sheet; with sort moved out, it holds four fields, so it was left as is.
- The UI is English-only; if an Arabic UI is wanted, it is a new feature (i18n + RTL), not a fix. D-26.

## Handoff → other phases

- **07 UI**
  - The product page's "Price history" heading and the chart card's own "Price History" title duplicate each other; one of them should go in the chart redesign.
  - Offer rows, the price box and the sort select use one-off classes; fold them into the design-system components (StoreRow/OfferRow, PriceTag, Select).
  - The home hero and the search page still use the generic centered layout; Figma is the reference.
- **08 Optimization**
  - Product pages still render per request (phase 05 finding); with the offers now first, ISR plus on-demand revalidation (A-13) would help most here.
- **09 SEO**
  - `/collections` was removed from `sitemap.ts` with U-08. The sitemap also lists `/watchlist`, a private, per-user page with nothing to index.
  - The home section is now "Most compared", which is also better anchor text for internal links.

## Decisions for Baraa

- **D-23 — Collections.** `/collections` is placeholder content: four static cards whose "Explore" buttons do nothing. I removed every link and promo to it, so nobody lands on a dead end, but the page itself still exists. **Recommendation:** delete the page. Real collections can come back as a feature built on data we have (for example "Biggest drops this week" from price history).
- **D-24 — Category filter.** The old "Category ID" field needed a database UUID, so I removed it. A usable category filter needs a small `GET /categories` endpoint and a select. **Recommendation:** add it in phase 08 or later, if you want browsing by category.
- **D-25 — Match confidence on offers.** Shoppers saw "Match 94%" per store (desktop only). It's internal jargon, and a low number reads as "this offer might be wrong". I removed it from the product page; the admin review queue still shows it. **Recommendation:** keep it removed. Low-confidence matches should be kept off product pages by the matcher, not labelled.
- **D-26 — Arabic UI.** Store titles in Arabic now render correctly, but the interface itself is English-only. **Recommendation:** decide whether an Arabic UI is a goal. If yes, it is its own project (i18n + RTL, about a phase of work).
- **D-21 (from phase 05, still open)** — store links bypass `/affiliate/go` click tracking. The new "Go to <store>" buttons keep the same direct links.
